# Distillation-for-KG-Generation

This repository contains the data pipelines, extraction scripts, and evaluation frameworks used to create the Small Language Models (SLMs) detailed in our paper: **Knowledge Distillation from Large Language Models for Scientific Knowledge Extraction**.

🔗 **Models & Data:** All the models created and used in this work are available through this [Zenodo link](#).

## 📂 Directories

### 💻 `src/`

* **`1_balanced_fetcher.py`**: This script queries the OpenAlex API to collect a balanced, daily dataset of AI-related scientific abstracts from high-quality publishers and preprint servers. It builds the foundational unstructured text corpus necessary for the downstream knowledge distillation pipeline.
* **`2_ner_deepseek.py`**: This asynchronous script acts as a teacher model by leveraging the DeepSeek API to perform batch Named Entity Recognition (NER) on the collected abstracts. It classifies text spans into distinct scientific categories and strictly formats the output using a predefined JSON schema.
* **`2_ner_gemini_research.py`**: Utilizing the Gemini API (specifically the `gemini-2.5-flash` model), this script executes concurrent batch NER on the scientific abstracts. It serves as another teacher LLM to identify domain-specific entities while enforcing structured JSON responses.
* **`2_ner_open_model.py`**: This script deploys an open-weight model locally via the HuggingFace pipeline to sequentially extract scientific entities from the abstracts. It includes custom regex parsing logic to robustly extract valid JSON outputs from markdown blocks generated by the model.
* **`2_ner_openai_research.py`**: This script utilizes the `gpt-4o-mini` model through the OpenAI API to serve as a teacher model for NER annotation. It leverages OpenAI's structured outputs parsing feature to ensure the extracted scientific entities rigidly adhere to the required extraction schema.
* **`3_train_NER_research.py`**: This script fine-tunes a transformer encoder for Named Entity Recognition (NER) using the synthetic annotations generated by the teacher LLMs. It features a robust character-offset alignment function to map text spans directly to subword tokens—bypassing common tokenizer splitting errors—and evaluates the final model against a unified blind test set.
* **`3_1_NER_eval_majority.py`**: This script evaluates the performance of a fine-tuned student NER model by comparing its predictions against a unified test set. It aligns the annotations generated by the different teacher models, aggregates them via token-level majority voting, and computes metrics such as precision, recall, and F1-score.
* **`4_rel_gemini.py`**: This asynchronous script uses the Gemini API to perform Relation Extraction (RE) by identifying semantic connections between previously extracted scientific entities. It enforces a strict, predefined ontology using Pydantic schemas and zero-temperature generation to extract precise canonical relationship triples.
* **`4_rel_openai.py`**: This script leverages the `gpt-4o-mini` model via the OpenAI API to act as a teacher model extracting relationship triples from scientific abstracts. It utilizes OpenAI's structured outputs parsing feature to map relationships into predefined canonical types while handling API rate limits through asynchronous concurrency.
* **`4_rel_deepseek.py`**: This asynchronous script employs the DeepSeek API to serve as a teacher model for extracting relation triples from scientific texts. It enforces a predefined canonical ontology by utilizing strict JSON validation schemas and a zero-temperature generation setting to prevent semantic drift.
* **`5_train_RE_research.py`**: This script fine-tunes a transformer-based sequence classification model to perform targeted Relation Extraction (RE) on scientific abstracts. It frames RE as a multi-class classification task, dynamically samples negative entity pairs to handle class imbalance, and evaluates the final trained weights on a blind test set.
* **`6_fecther_openalex.py`**: This data acquisition script utilizes the OpenAlex API to perform unrestricted, high-volume bulk downloads of AI-related research papers over a specific timeframe. It filters for high-quality publishers and rebuilds abstract texts from inverted indices to construct a large-scale corpus for applying the extraction pipeline.
* **`7_NER_apply.py`**: This script deploys a fine-tuned Named Entity Recognition (NER) student model to extract scientific entities from newly collected, unseen research abstracts. It incorporates advanced post-processing techniques, including boundary expansion, acronym resolution, and confidence-based deduplication, to ensure the extracted entities are clean and standardized.
* **`8_RE_apply.py`**: This script applies a fully trained Relation Extraction (RE) student model to classify semantic connections between the entities identified in unseen scientific abstracts. By generating permutations of entity pairs and utilizing a strict confidence threshold, it extracts and retains only highly probable, schema-compliant relationship triples.
* **`9_sample_eval.py`**: This script analyzes the output of the extraction pipeline to select a subset of the most information-dense abstracts for human or automated evaluation. It computes a richness score based on the number of triples, unique predicates, and average confidence to isolate high-quality extraction samples.
* **`10_1_deepseek_zero_shot_v2.py`**: This script evaluates the DeepSeek API in a zero-shot setting by explicitly injecting strict JSON ontology definitions into the prompt. This constrained prompting strategy forces the model to adhere exclusively to predefined canonical relationships during extraction.
* **`10_1_deepseek_zero_shot.py`**: This script performs zero-shot knowledge extraction using the DeepSeek model with a basic prompt that lists permissible scientific entities and predicates. It serves as a baseline configuration to measure the model's natural extraction capabilities and schema adherence without strict JSON ontology definitions.
* **`10_1_gemini_zero_shot_v2.py`**: Utilizing concurrent threads, this script evaluates the Gemini API's zero-shot extraction performance using strict ontology constraint prompts. It includes robust error handling and exponential backoff mechanisms to manage rate limits and billing errors during high-volume processing.
* **`10_1_gemini_zero_shot.py`**: This script benchmarks the Gemini model's baseline zero-shot extraction capabilities by providing only a simple list of valid scientific entities and predicates. It features a checkpointing system to resume interrupted extraction tasks and handle API rate limits.
* **`10_1_gpt4o_zero_shot_v2.py`**: This script deploys the `gpt-4o-mini` model in a zero-shot capacity, enforcing strict schema compliance by embedding detailed ontology definitions directly into the prompt. It leverages OpenAI's structured outputs parsing to guarantee the extracted triples conform to the provided JSON schema.
* **`10_1_gpt4o_zero_shot.py`**: This script acts as a baseline zero-shot evaluator for the `gpt-4o-mini` model, using a simplified prompt without explicit JSON ontology definitions. It extracts knowledge triples asynchronously while relying on OpenAI's native structured outputs framework for initial formatting.
* **`11_1_deepseek_judge.py`**: This asynchronous script deploys the DeepSeek API as an automated evaluator to grade the correctness of extracted knowledge triples. It uses strict JSON schemas to batch-score triples as either correct or hallucinated, featuring a resume mechanism to prevent redundant API calls.
* **`11_1_gemini_judge.py`**: Utilizing concurrent threads, this script employs the Gemini API to act as an automated judge that validates extracted relationship triples against their source abstracts. It handles batch grading with structured JSON responses and includes robust checkpointing to seamlessly resume interrupted evaluation runs.
* **`11_1_gpt4o_judge.py`**: This script leverages the `gpt-4o-mini` model via the OpenAI API to automatically assess the accuracy of extracted knowledge graph triples. It utilizes OpenAI's structured outputs to enforce boolean grading standards and processes the evaluations asynchronously with built-in checkpointing.
* **`12_eval.py`**: This script evaluates the performance of the extraction pipelines by comparing generated triples against automated judge scores and a strict predefined ontology. It calculates comprehensive metrics including micro/macro precision, recall, F1-scores, hallucination rates, and pairwise Jaccard similarities, exporting the results to detailed CSV and text reports.
* **`13_manual_eval_analyzer.py`**: This script analyzes human annotation data from an Excel file to establish ground truth and calculates inter-annotator agreement using Fleiss' Kappa. It then benchmarks the performance of various LLM judges against this human consensus, executing statistical significance tests like McNemar's and Fisher's exact tests to validate the results.
* **`13_sample_for_human_eval.py`**: This script curates a balanced and deduplicated subset of extracted triples from multiple models to create a structured Excel workbook for human evaluation. It employs stratified sampling to prioritize rare predicates and automatically formats the abstracts with bolded entities to assist researchers during manual grading.
* **`14_scalability_metrics.py`**: This script analyzes the token usage of the extraction process to evaluate the computational and economic scalability of the models. It uses the `tiktoken` library to compute the average number of input and output tokens per abstract under different prompt configurations.

### 🧠 `resources/`

* **`aikg_schema`**: This file contains the formal OWL ontology for the Scientific AI Knowledge Graph, written in Turtle syntax. It defines the core research entities (e.g., Algorithm, Dataset, Hardware) and the structural object properties required to map reified scientific statements.
* **`relationships.json`**: This configuration file defines the strict vocabulary of 12 canonical relationships (such as `USES`, `ADDRESSES`, and `EVALUATED_ON`) used by the Relation Extraction models. It enforces schema compliance by providing explicit definitions and linguistic examples for each allowable predicate.

### 📊 `eval/ (zipped)` 

The `eval/` directory contains the complete evaluation ecosystem for the knowledge extraction pipeline. It hosts the foundational baseline datasets, the raw zero-shot triples extracted by frontier LLMs (DeepSeek, Gemini, and GPT-4o), and the comprehensive automated judge results. The directory also includes the `human_annotation_sample.xlsx` workbook containing the triples manually reviewed by domain experts to establish the human-consensus ground truth used for validating the automated judges and calculating final extraction precision.
